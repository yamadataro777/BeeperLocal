# 本家BeeperのUI/UXとBeeperLocalへの採用案

調査日: 2026-10-03 / 比較対象: Beeper Desktopの公式ヘルプ・公式掲載画像、BeeperLocal 0.9.1の実装と架空データ画面。

**採用の軸は「複数サービスの会話を一か所で見渡し、対応が必要な会話から処理する」こと。最優先は統合Inbox、未読・下書きの絞り込み、サービス横断検索。** 現在のBeeperLocalにある3領域の画面構成は活かせる。大きな差は、その画面で何を優先して見せるかにある。

以下の「観測」は公開資料で確認した事実。「解釈」「提案」はBeeperLocal向けの設計判断であり、本家の内部仕様や実測値ではない。本家の個人アカウントにはログインしていない。今回の実装は3サービスのMCP対応と設定画面の共通化までで、以下のInbox再設計は未実装。

## 1. 本家を言語化する

| 観点 | 公式資料・画面で確認したこと | UXとしての解釈 |
|---|---|---|
| 主な入口 | 接続サービスをまとめたInbox。未読、未整理の既読、下書きを扱う [1] | 「どのアプリだったか」を思い出す前に、会話へ入れる |
| 情報の配置 | 細い左レール、会話一覧、右側の会話領域。表示範囲・検索・フィルターの操作が一覧上部に集まる [2] | 範囲を決める→会話を選ぶ→読む・返す、という視線の流れ |
| 一覧の操作 | 未読・下書き・未返信・グループで絞り込み。ピン留め、複数選択もある [1][2] | 件数が増えても「次に見る会話」を決めやすい |
| アーカイブ | Inboxから一時的に外し、新しい活動で戻す。本家サービス側のアーカイブとは別 [1] | 消去せず「いったん対応済み」にできる |
| 優先度 | Low Priorityは専用の場所へ移し通知を抑制。メンション等は例外 [1] | 会話の重要さと到着順を分ける |
| ラベル | DesktopではInboxのメニューや会話情報から会話をまとめられる [3] | 仕事・家族等、サービスをまたぐ自分の分類を作れる |
| 検索 | Cmd/Ctrl+K。アカウント、送受信・会話種別、期間、メディア種別で絞れる [4] | 正確なキーワードを覚えていなくても探す手掛かりを足せる |
| キーボード | 設定にショートカット一覧があり、割り当てを編集できる [5] | 頻出操作を覚えながら短縮できる |
| 人を中心にする方向 | 2026年8月に同じ人との複数ネットワークの会話をまとめる機能を告知 [6] | 長期的には「アプリ」より「相手」を主語にしている |

**見た目の観察:** 公式のDesktop画像は、低彩度の背景と細い区切りを使い、色を選択項目・未読バッジ・サービスアイコンへ集中させている。アイコンのレールは省スペースで、フィルターメニューには件数・選択マーク・ショートカットが並ぶ。[2] 会話内容はぼかされているため、文字サイズ、吹き出しの細部、実際の操作速度までは評価していない。

**一連の体験の解釈:** 全体を見る → 必要なものへ絞る → 返信する／後で扱う → 一覧から片付ける。この循環がInboxの価値を作る。BeeperLocalも、新着を受け取れることに加え、「今日残っている対応」が見えると日常の利用価値が高まる。

## 2. 現在のBeeperLocalとの差

0.9.1の根拠は `desktop/src/main.tsx`、`desktop/src/SettingsPanel.tsx`、`desktop/src/HelpPanel.tsx`、`beeperlocal/desktop_sync.py`、`beeperlocal/desktop_control.py` と画面テスト。

| 項目 | 現状 | 活かせるもの／不足 |
|---|---|---|
| ナビゲーション | サービスレール→選択サービスの会話→本文 | 3領域はそのまま使える。全サービスを並べる入口がない |
| 新着 | バックグラウンド取得、サービス別と全体の未読件数 | 受信と件数集計はある。未読だけの横断一覧がない |
| 下書き | 会話ごとにメモリ保持。終了すると消える | 安全な宛先分離はある。一覧に下書きが見えない |
| 整理 | ローカル削除・保存停止 | アーカイブ、ピン、ラベル、低優先度はない |
| 検索 | Cmd+K、選択サービスの保存済み本文を検索 | キー操作を再利用できる。横断検索・期間フィルターがない |
| 状態の表示 | 接続・受信・取得範囲を本文付近に常時表示 | 情報は正確。通常時の説明が会話領域を占める |
| 設定 | 今回5サービスとも「サービス接続／MCP接続／保存管理」に統一 | 同じ操作を覚えれば各サービスへ適用できる |
| 安全な返信 | サービス・アカウント・会話の照合、保存してから送信、結果不明時は自動再送しない | 統合Inboxにしても維持する必要がある |

## 3. 真似する範囲と優先順位

規模は既存構造からの相対見積もり（小・中・大）。日数の見積もりではない。

| 優先 | 採用案 | ユーザーが得るもの | 規模・前提 | 完了の判定 |
|---|---|---|---|---|
| P0-1 | **「すべて」の統合Inbox**をサービス一覧の先頭へ | 5サービスを巡回せず新着を確認 | 中。各Coreの一覧を表示用に集約 | 同名の相手でもサービスバッジで区別。クリック時に正しいCoreへ切り替わり、宛先・下書き・未読が混ざらない |
| P0-2 | **未読／下書き**のフィルターと一覧上の状態表示 | 返信漏れや書きかけを見つける | 小〜中。まず下書きは現状どおり起動中だけ | フィルター件数と表示が一致。下書きが別会話へ移らない。0件時は「未読はありません」等を表示 |
| P0-3 | **横断検索**とサービス選択 | 投稿先を忘れても見つける | 中。各DBをメモリ上で限定復号し結果統合 | 結果にサービスを表示。対象範囲・検索上限・一部サービスの失敗を示す。平文FTSを追加しない |
| P0-4 | **通常時の状態表示を短くする** | 会話本文に集中できる | 小。正常時は短い状態、詳細は展開 | 切断・保存停止・結果不明は目立つ場所に残る。取得していない履歴を「取得済み」と誤認させない |
| P1-1 | **ピン留めとローカルアーカイブ** | よく使う会話を固定し、完了した会話を片付ける | 中。暗号化した会話設定と復帰条件が必要 | 元サービスのデータを変更しない。操作の取消ができ、新しい受信でInboxに戻る。過去履歴の追加取得だけで戻さない |
| P1-2 | **次の未読・一覧移動・検索のキー操作** | 大量の会話を素早く処理 | 小〜中。フォーカスとIMEを考慮 | 入力中のキーを奪わない。設定画面でキーを発見できる。マウス操作でも同じことができる |
| P1-3 | **ラベルと複数選択** | 仕事・私用等で整理 | 中。暗号化した分類・一括取消 | ラベルを消しても会話は消えない。一括処理の対象件数を表示 |
| P2 | **低優先度・未返信・リマインダー** | 注意を向ける順序を調整 | 中〜大。通知例外、送信結果、再起動後の時刻処理が必要 | 「最後が相手の発言」と「返信義務がある」を区別。メンション未取得時に例外通知を保証しない |
| 保留 | **同じ人の会話を結合** | サービスを意識せず会話 | 大。明示的な人物対応付けと送信経路選択が必要 | 表示名だけで自動結合しない。送信先サービスを確認でき、いつでも分離できる |

最初の実装単位は **P0-1とP0-2**。これで「統合メッセンジャーを開けば、残っている会話が分かる」という変化が出る。続いてP0-3とP0-4、その後アーカイブへ進む。

## 5. 採用時に守ること

- 現在のサービス別Core・暗号化DB・MCP権限は維持し、まず一覧の表示を統合する。統合Inboxの追加だけでAIの権限を広げない。
- ピン・ラベル・アーカイブ・永続下書きは本文に紐づく情報として暗号化保存する。現状の下書きを永続化する場合は別の変更として扱う。
- 本家のアーカイブ復帰条件を丸ごと保証せず、最初は検知できる新規受信を条件にする。同期で既存の古いメッセージが増えた場合と区別する。
- 通話、入力中表示、既読、リアクション、参加管理はサービス側の対応が必要。UIだけを追加して動作するようには見せない。
- スマートフォンのスワイプ操作、Spacebar、Minimal/ProをDesktopの現行仕様と混同しない。8月告知の新SpacebarはiOS/Android向け。[6]
- 配置・分類・操作の考え方を参考にし、Beeperのロゴ、画像、アイコンセット、文面の複製は行わない。
