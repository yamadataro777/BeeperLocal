## L1: LINE同期と再開

最初の差分として、通常daemon/watch開始前の直近履歴回収、messageと同期receiptの原子的暗号化保存、`sync-status line`を実装した。これはbounded recoveryで、完全なincremental cursorではない。

次の作業:

1. line-cliとCore間のcursor/ack契約を決め、commit前に受信位置が確定してしまう境界を解消する。
2. 停止中のメッセージ→再開→重複なし、再取得した編集textの更新、履歴上限超過を区別して実機検証する。
3. 削除イベントに対応しない初期版では、履歴不在を削除と推定しない。Group/media/read receipt/unsendは範囲外のまま。
4. 0.6.0で追加した再接続・致命的エラー・上限到達の状態表示を、長時間・スリープ・実断線・認証失効で実機検証する。

手元で利用する追加コマンド:

```bash
./run.sh daemon line --recovery-limit 100
./run.sh sync-status line
```

前者は受信を継続しCtrl-Cで停止。後者は別Terminalで実行でき、前回回収の記録だけを読む。送信は行わない。
