# デスクトップUI設計 v0.1

2026-09-30 / 初期版を実装・ビルド済み。macOS、Tauri 2 + React/TypeScript、既存Python Coreを利用。

初期版の実装範囲と制限は[DESKTOP_APP.md](DESKTOP_APP.md)、正確なIPCは[ADR_DESKTOP.md](ADR_DESKTOP.md)を参照。以下は設計仕様を含み、将来のprovider切替・履歴ページング等まで実装済みという意味ではない。Core 187件・fixture UI 6件PASS。Macウィンドウ起動確認済み、実データ連携はKeychain許可待ち。

## 画面構成

```text
┌─────────────────────────────────────────────────────────────┐
│ BeeperLocal                 [ローカル検索 ⌘K]    [接続設定]  │
├───────────┬──────────────────────┬──────────────────────────┤
│ すべて    │ 会話を絞り込む       │ 相手名  LINE             │
│ LINE      │                      │ 最終同期 / 接続状態       │
│ Instagram │ 相手A       時刻     ├──────────────────────────┤
│ 𝕏         │ LINE ・ 最終本文     │ 日付                     │
│           │                      │        メッセージ履歴    │
│           │ 相手B       時刻     │                          │
│           │ LINE ・ 最終本文     ├──────────────────────────┤
│           │                      │ [メッセージを入力      ] │
│           │                      │                  [送信]  │
└───────────┴──────────────────────┴──────────────────────────┘
```

初期幅1,180px・高さ780px。rail・会話一覧・本文の3領域。狭い画面では会話一覧/履歴を一画面ずつ表示し「会話一覧へ戻る」を設ける。設定はモーダルダイアログ、検索結果は会話一覧領域に出し、結果選択で該当メッセージへ移動する。

LINEが最初の利用可能なprovider。IG/𝕏は「準備中」と表示して接続操作を無効化し、connectorのcapabilityが揃った時点で同じ画面に追加する。色だけでproviderやエラーを区別せず、名前・ラベルを併記する。

## 普段の操作

1. 起動時はローカル保存済み会話と履歴を先に表示する。再接続中でも既存履歴を読める。
2. LINEの既存sessionをCoreで復元。未ログインなら本人操作の接続手順へ案内する。
3. 会話を選ぶと履歴を時刻順表示。別会話へ送信先が残らないよう、composerは会話identityに結び付ける。
4. 送信先・providerをヘッダーに常時表示。Enterは改行、⌘Enterまたは送信ボタンが明示的な送信操作。日本語IME変換中のキー操作では送らない。
5. 受信で履歴・会話順を更新する。履歴の過去位置を読んでいる間は強制スクロールせず「新着へ」ボタンを出す。
6. 検索は保存済みLINEデータのみ。未取得の履歴まで検索したとは表示しない。他providerの検索UIは今後追加する。

## 状態と表示

| 状態 | 画面表示・操作 |
|---|---|
| 未接続 | 接続する。履歴があれば閲覧可能 |
| 接続確認中 / 履歴回収中 | 状態と最終保存時刻。既存履歴は表示を維持 |
| 受信待機中 | プロセス起動を示す。server接続確認なしで「接続済み」と断定しない |
| 再接続待ち / ネットワーク停止 | 最終更新時刻と再試行。送信は無効化し下書きを保持 |
| 再認証が必要 | 固定メッセージと本人の再ログイン導線。raw例外なし |
| 履歴回収の範囲に制限 | 直近N件だけ確認済み。過去履歴や削除が完全同期済みとは表示しない |
| 検索結果0件 | 「保存済みの検索対象範囲では見つかりません」。走査上限を併記 |
| DB/Keychain失敗 | 読み書きを止め、復旧手順を表示。空DBとして上書きしない |
| Group/media等の未対応 | 非対応を明示し、空本文の通常textと混同しない |

## 送信状態

`下書き → 送信処理中 → サービス受付済み → ローカル保存済み`を区別する。サービス受付済みは相手端末への配送確認・既読の意味ではない。

応答喪失は「送信結果不明」。自動再送しない。履歴を再取得して結果を確認する導線を出す。受付済みでDB保存が失敗した場合も再送せず回収する。未対応のproviderではcomposerを無効化する。永続送信ledger、request ID、二重クリック抑止、クラッシュ後の未確定状態復元を実装した。LINE側にidempotency保証がないため、未確定項目を自動再送しない。

初期版はprovider由来の未読数・既読・配送マークを表示しない。根拠がない数値を0や推定値で補わない。将来ローカル未読を追加する場合はprovider既読と別の意味として設計する。

## CoreとUIの契約

Tauriの管理下でPyInstallerで同梱した固定Python Coreを起動し、private stdin/stdoutの構造化IPCを使う。UIへ公開するのはallowlistのtyped commandだけ。配布物のビルドと起動は確認済み。以下は設計上の操作区分で、実APIは`core_request`の`op`として`ADR_DESKTOP.md`に記録している。

| command | 入出力の境界 |
|---|---|
| `list_conversations(provider?)` | scoped opaque ID、表示名、provider、最新保存時刻 |
| `get_messages(conversationId, before?, limit)` | opaque IDでCoreがcanonical identityを解決。上限あり |
| `search_messages(query, provider?, limit)` | メモリで検索、対象上限・結果を返す。queryをログへ残さない |
| `get_sync_status(conversationId)` | 最終回収・範囲制限・固定error code。cursorやtokenを返さない |
| `send_text(conversationId, text, clientRequestId)` | Coreで宛先・capability・重複操作を検証。raw shell/HTTP入力なし |
| `start_sync(provider)` / `stop_sync(provider)` | 二重daemonを防ぎ、停止完了を確認 |

画面はprovider token、Keychain鍵、DBファイル、任意shell、任意HTTPを扱わない。本文・相手名は意図したUIにだけ表示し、console、telemetry、localStorage、エラーレポートへ保存しない。通知本文は初期OFF。表示名をidentityや送信先解決に使わない。

## UI実装の受入条件

- ローカルの実LINE会話・履歴・検索を同じidentityで表示できる。
- 初期版のwatch対象は選択済み1会話と明示する。catalog全件が受信同期済みであるように見せない。複数会話購読は別実装。
- 空状態、取得中、ネットワーク停止、再認証、DB失敗、送信結果不明を再現して確認する。
- ⌘K、会話のキーボード移動、⌘Enter、IME入力、focus復帰、読み上げlabelが機能する。
- 100/500会話の表示・切替で固まらない。500件上限では「全件取得済み」と表示しない。
- provider切替で下書き・宛先を取り違えず、連打・再起動で送信を重複させない。
- UI fixture検証と実機での送受信確認を別の証拠として記録する。
