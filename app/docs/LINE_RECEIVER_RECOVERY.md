# LINE受信の継続復旧 — Desktop 0.8.3

2026-10-01。通常の `../BeeperLocal.app` を、同じDeveloper IDで署名した0.8.3へ更新。

## 原因と修正

旧版は、一時的なLINE通信エラー／受信CLI終了が続くと、1・2・4・8・16・30秒の再試行を使い切って `SYNC_RETRY_EXHAUSTED` で受信タスクを終了していた。定期履歴回収側にも上限到達時に受信を止める経路があった。このため通信が戻っても、手動再接続まで受信が戻らなかった。

今回の修正は、この「一時障害が長引くと復帰できなくなる」原因を対象にする。最初の通信エラーの原因は、保存されている固定エラー情報だけでは特定できない。以前のスリープ試験より前からLINE子プロセスが不在だったため、スリープが最初の原因とは断定しない。

- 一時的な `LINE_REQUEST_FAILED` / `LINE_WATCH_FAILED` / `NETWORK_ERROR` は、短い再試行の後も60秒間隔で自動再確認する。定期回収の一時障害でも受信を永久停止しない。
- 再接続時は選択会話の直近100件以内を回収し、既存の重複判定・暗号化保存を経て受信を再開する。
- 開始通知の直後にCLIが終了する場合、古い開始通知が後から「受信待機中」を表示する競合を修正した。
- 再試行待ちは最大5秒の区切りで壁時計と経過時計を確認する。スリープ中に待ち時間が過ぎていれば、復帰後に残りの長い待ちを続けない。壁時計が後退しても待ちを延長しない。
- 認証、保存、想定外データのエラーは引き続き停止する。明示した受信停止・保存停止でも再試行を取り消す。
- 接続回復時に古いエラーを消去する。送信結果不明の要求を再送する経路は追加していない。

画面には長い再試行待ちで「LINEとの通信が回復するのを待っています。1分間隔で自動的に再確認します。」と表示する。
