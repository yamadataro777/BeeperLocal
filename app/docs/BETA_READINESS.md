# ベータ提供に向けた点検と改善 — 0.9.5

## 0.9.5 Slack公開認証の設定（2026-10-03）

本人承認を受け、Slack側の接続先を`beeperlocal://oauth/slack`へ変更し、他ワークスペースへの配布を有効化した。PKCE・12 user scopes・token rotationを保存済みmanifestで確認し、公開Client IDをアプリに同梱する。以下の0.9.3以前の公証・Slack未設定という記述は当時の履歴。各版の公証と同梱設定の結果は、ZIP内`distribution-checks.json`を参照する。

0.9.4でMessenger会話切替時のKeychain書換えを廃止し、暗号化ローカルDBへ選択状態を保存するようにした。起動中の重複アクセス抑止も通常アプリに反映した。初回のOS許可は本人操作であり、実利用での確認反復が完全になくなったとはまだ確認していない。

別Macで5サービスすべての本人ログイン・テキスト送受信・画像着信・再起動後の保存履歴を確認する受入は未完了。設定保存と公証の成功から実連携の成功を推測しない。

## 今回見つけて修正した問題

| 問題 | 改善 | 検証方法 |
|---|---|---|
| LINEの削除要求に画面が付けるproviderをRustが拒否し、実アプリで削除操作が成立しない | LINE専用コマンドに明示的なLINE scopeを受け付け、他providerや余分な引数は拒否 | Rustの実serde境界テスト＋従来のPython削除テスト。実ユーザーデータは削除しない |
| Instagramが短い再試行を使い切ると、回線が戻っても永久停止 | 以降も60秒間隔で再接続。認証・保存・復号の異常と明示停止は停止を維持 | 複数回切断→低頻度再試行→復帰、停止による中断のfixture試験 |
| Slackも通信障害が長引くと定期取得を打ち切る | 以降も300秒間隔で再確認し、Retry-Afterも尊重。スリープ復帰を考慮した待機を共用 | 低頻度再試行・復帰・明示停止のfixture試験 |
| 結果不明の送信後に、同じ下書きを再度クリックすると新UUIDで二重送信し得る | 同じ未確定本文の再送を保留し、履歴・相手側で未着を確認するチェックを要求。キーボード送信も同じ条件 | 不明→クリック抑止→確認後1回、入力変更、既存の永続送信台帳テスト |
| Core終了後も画面が接続済みのままで送信できそうに見える | 即座にオフラインへ切替え送信無効化。履歴・下書きは保持 | fatalイベントの画面テスト |
| 検索が失敗すると前の検索結果が残り、新しい語の結果に見える | 検索開始時に古い結果を消去し、検索欄に失敗を表示。次の検索で復帰 | 1件一致→失敗→別検索の画面テスト |
| サービスの最新会話一覧から外れた保存済み会話が検索できない | 現在のアカウントの保存済み会話全体を対象にし、一覧にない検索結果からも開ける | 一覧から外した会話のCore検索・画面で履歴を表示。他accountの分離は維持 |
| 保存停止で初回画面が空のとき、接続の失敗を繰り返してしまう | 再開方法を表示し、接続・送信・履歴更新を明示的に無効化 | 保存停止状態で起動してconnect要求が0回であることを確認 |
| 640px幅では初回エラーが隠れた右ペインにしか出ない | 会話一覧にも状態と接続設定への入口を表示。アイコンだけの設定にも名前を付与 | 640×500の画面テスト |
| InstagramとSlackの初回設定が開発フォルダやCLI操作を前提にしている | アプリに専用接続ファイルを同梱し、設定ボタンからTerminalの入力画面を開く。対象サービスの受信を先に停止。Python不要 | 日本語・空白パス、OS標準PATHだけのコピー、非対話入力拒否、トークン非出力を検証 |
| MCPトークン発行後に管理画面の再読込が失敗すると、一度だけのトークンを表示できない | 発行結果を先に保持・表示してから後続状態を更新 | 登録成功後のmanagement失敗を注入した画面テスト |
| サービス別の制限が散在し、友人からの不具合報告に必要な情報がない | アプリ内に使い方・対応範囲と、内容・相手名・ID・トークンを含まない診断情報を追加 | 診断情報の項目と秘匿対象が含まれないことを確認 |
| 古いNodeでビルドすると長い内部例外で停止する | ビルド開始前にNodeバージョンを検査し、enginesと.nvmrcを追加 | 非対応Nodeでの早期停止・対応Nodeでのproduction build |

下書きはprovider＋会話で明示的に分離し、LINEのローカル削除で他サービスの下書きを消さない。本文・検索語・下書きをlocalStorageへ保存する変更はしていない。新しいログイン入口も認証情報をWebViewやコマンド引数へ渡さない。

- LINEの全過去履歴、Messengerの暗号化バックアップ、全サービスの完全な削除・編集・既読同期、グループ作成は残る。画像送信は0.9.3で実装したが、実着信は未検証。対応済み範囲と境界はINBOX_0_9.mdに明示。
