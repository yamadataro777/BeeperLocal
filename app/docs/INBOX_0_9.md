# BeeperLocal 0.9.0 ベータ候補 — 実装内容と公開設定

2026-10-03。0.8.7候補からの拡張です。通常配置の0.8.5は別管理で、この資料は0.9.0の実機疎通や一般公開完了を示しません。

## 今回の実装

- 接続したサービスの会話を順番に取得します。画面で選択している会話はバックグラウンド取得で変わりません。一度接続したサービスは次回起動でも再接続し、保存を停止したサービスは停止を維持します。
- 未読はこのMacで管理します。初回取り込み・過去履歴の追加では未読を増やさず、その後の受信で増やします。フォーカスのある画面で末尾まで表示した分だけ既読にします。元サービスの既読状態とは同期しません。
- サイドバーでサービス別・合計の未読を表示します。通知は明示的に有効にした後だけ行い、macOS通知にはサービス名だけを表示します。本文・相手名は含めません。
- 保存済み履歴を100件ずつ過去へ追加表示できます。Instagram・Slack・Xは「この会話の過去履歴を取得」「全会話の過去履歴を取得」で、APIが返す終端まで順番に読みます。カーソル・本文・未読状態は同じ暗号化DBトランザクションで保存し、再起動後も続きから取得します。
- Messengerは登録済み暗号化端末と同じ接続で1対1テキストを送信します。送信要求を先に保存し、SDKで受理された結果と端末状態を保存してから完了を表示します。二重クリックを抑止し、結果不明時に自動再送しません。
- XとInstagramの参加済みグループを会話として扱います。新規グループ作成・参加・メンバー変更は行いません。
- XとInstagramの受信した画像・動画・音声をクリックして表示できます。1添付4MiBまで。画像はデコード・再エンコード、Xの暗号化添付は署名済み鍵と暗号ストリームの認証を確認します。未対応形式・配信期限切れ・容量超過は取得失敗表示になります。ファイルのアップロード・添付送信は未対応です。
- 全5サービスに保存管理を用意しました。対象確認で保存・受信を停止し、2分以内の確認でそのアカウントのローカル会話・本文・取得情報・送信内容・MCP権限を削除します。他のサービス、ログイン、暗号鍵は保持します。二重送信防止の識別ハッシュは残します。X内部の重複保存本文も削除対象です。Messengerの旧受信キャッシュを取り込む処理と削除処理は2026-10-03の開発ソースで廃止しました。端末Keychainは保持します。

会話数が増えると、各会話が巡回されるまでの時間も増えます。アプリ終了中・Macのスリープ中は受信しません。一覧は約5分ごとに更新します。Slackの取得制限はワークスペース・アプリ配布形態・保存期間に左右されます。スレッド巡回一覧は1会話10,000スレッドまでです。検索は従来どおり保存済み最新10,000件を走査し最大50結果で、過去ページの閲覧とは別の制限です。

削除済みの本文は検索・履歴から除外し、削除識別ハッシュで古い履歴からの復活を抑えます。「ページに見つからない」という理由だけで本文を消すことはありません。全サービスのすべての削除・編集を完全同期できる状態ではありません。

## SlackのブラウザOAuth

Slackの公開クライアント向けPKCE（S256）を実装しました。ブラウザでユーザー権限を承認し、localhostコールバックのstateを照合してコード交換します。Client Secretは不要です。コード・verifier・トークンはWebViewへ渡しません。アクセストークンとローテーションするrefresh tokenはmacOS Keychainの同じレコードへ保存します。

配布者が行う設定:

1. `slack-send-app-manifest.json`をもとに管理するSlackアプリを設定し、PKCE・token rotation・User scopesを有効にする。
2. Redirect URLを`http://localhost:28643/oauth/slack`に登録する。
3. 公開Client IDを`beeperlocal/release_config.py`の`SLACK_CLIENT_ID`へ設定して再ビルドする。Client Secret・ユーザートークンはソースやチャットへ書かない。
4. 外部ワークスペース向けの配布設定と必要な承認をSlack側で完了し、実ブラウザで接続・更新・取消・再認証を検証する。

現在の候補はClient IDが未設定です。ボタンは固定エラーで設定不足を案内します。既存のKeychain連携は維持します。ほかのサービスをSlack OAuthへ置き換えるものではなく、Instagramの初回連携は現行の本人ログイン設定画面、LINEはQR、X/Messengerは専用ログイン画面を使います。

根拠: [Slack PKCE](https://docs.slack.dev/authentication/using-pkce/)、[アプリmanifest](https://docs.slack.dev/reference/app-manifest/)、[履歴APIの制限](https://docs.slack.dev/reference/methods/conversations.history/)。PKCE有効化は一方向の設定です。PKCEのrefresh tokenには30日の期限があり、期限切れ時は再認証が必要です。

## 署名付き自動更新

起動後と6時間ごとに更新を確認します。適用はユーザーの「適用して再起動」操作で開始し、下書き・接続や送信の処理中・ログイン中は適用できません。更新ファイルとバージョンの署名を確認した後で受信とMCPを停止し、アプリを置き換えて再起動します。ダウンロードは512MiBを上限とし、失敗時に未検証ファイルを適用しません。

公開前の手順:

1. `desktop/src-tauri/update-channel.json`の`endpoint`にHTTPSの更新manifest URLを設定する。
2. `.desktop-venv/bin/python -B scripts/build-update.py init-key`で署名鍵をmacOS Keychainへ作成し、対応する公開鍵だけを同JSONへ保存する。既存鍵は再利用し、不一致なら停止する。
3. 通常のDeveloper ID署名付きrelease buildを実行する。
4. 最終署名済み`.app`に対し`.desktop-venv/bin/python -B scripts/build-update.py package --app <appのパス> --output <出力先> --url <公開するapp.tar.gzのHTTPS URL>`を実行する。
5. 生成された`.app.tar.gz`、`.sig`、`latest.json`を設定した配布先へ公開し、現行形式での更新・再起動・保存データ維持を別のテスト環境で確認する。旧形式の移行・互換を追加しない。

秘密鍵のファイル・環境変数への書き出しは行いません。Tauriが作る途中段階のアーカイブを配るのではなく、最後のApple署名を終えたアプリをアーカイブして署名します。現在の候補は配布URL・公開鍵が未設定で、更新の公開・実適用は未検証です。根拠: [Tauri updater](https://v2.tauri.app/plugin/updater/)。
