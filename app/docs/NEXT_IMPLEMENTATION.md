# 次工程 — 販売初版を完成させる

更新: 2026-10-01。ユーザーが選んだ到達点は「販売できる最初の製品」。基準は[販売初版までの開発計画](IMPLEMENTATION_PLAN.md)、現状の証拠は[PROJECT_STATE](PROJECT_STATE.md)。主担当だけで進める。

## 次に完成させるもの

**まずLINEを軸にした初版の配布条件と、実際のAIにつながる導入経路を確定する。** 既存の販売準備に合わせて12/1を目標とする。新規サービスの追加を発売の前提に増やさない。

### 1. G0: 販売対象・配布条件の整理

- line-cliによる本人アカウント接続の商用提供・データ利用条件を確認し、適用条件と未解決点を一覧にする。MITライセンスとサービス利用許可を分ける。
- 初版に同梱するコード・ライブラリ・ライセンス・改変差分を特定する。IG/XのAGPL部品は、対象外なら販売ビルドからの除外を設計し、同梱するならソース提供等の対応を決める。既存開発版の削除や認証方式の無断変更はしない。
- Slackは既存実装を維持する。商用配布の別契約、ローカル保持・外部AI連携の用途適合が未確認なので、販売対応として確約しない。
- 完了物: 対象方式、根拠、確認日、必要な許可、同梱部品、対応方針、初版採否をまとめた一覧。確認が済むまで販売可能と表示しない。

### 2. G1: 対応AI 1製品との実接続

- 利用者が選ぶAIのローカルMCP対応・認証方式を確認し、バージョン付きの接続手順を用意する。現方式は127.0.0.1のStreamable HTTPと手動Bearer。
- 利用者が許可した会話で参照→検索→返信案を確認する。送信は権限を分け、承認済みの宛先・本文で1回の受付・相手側受信・再起動検索まで確認する。
- 権限取り消し、別会話/別アカウント、アプリ再起動、結果不明送信の重複抑止を確認する。秘密をチャット・ファイル・診断ログへ出さない。
- 初回接続、許可対象、最終取得、検索上限、停止・失効を利用者が理解できる案内へまとめる。
- 完了物: 実AIでの証拠、設定ガイド、対応表。HTTP fixture試験を実AI接続成功に転用しない。

### 3. G2: LINEの日常運用

- 基準は正式署名付き0.8.3。[受信復旧記録](LINE_RECEIVER_RECOVERY.md)にある7回中断後の復帰を保持する。
- 実スリープ/復帰、物理回線断/復旧、24時間運転、認証失効と復帰、再起動・更新後の保存/検索を確認する。
- 直近100件の回収境界・上限超過と欠落の可能性を明示する。完全なcursor/ack同期の完成扱いにしない。
- 保存停止・権限失効・削除は同意した試験用データで確認する。既存会話の削除や追加の実送信は検証手順だけで自動許可されない。

### 4. G3以降: 配布・購入・試用

- Developer ID署名を再利用し、公証済みの配布候補を作る。手動更新・復旧・再ダウンロードを検証する。
- 別Macの初回導入確認は本人指定どおり後半。初版で対応するmacOS版を実機結果から決める。
- 既存価格と販売ページに合わせ、購入からファイル受け渡し・問い合わせまでの手順をテストする。本人入力・Stripe最終申請は本人作業として区別する。
- 配布条件を満たしてから3〜5人・各7日間の試用へ進み、11/28〜30に発売判定。12/1は条件付きの販売開始予定。
