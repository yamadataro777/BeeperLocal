# ADR: Phase 0はGUIより先に2サービスの接続実証を行う

決定日: 2026-09-27
対象: 今回追加したCLI PoC。元のMVP設計書そのものは上書きしない。

## 決定

今回の成果物はPython 3.11以上のCLIとし、Telegram＋Slackから選択した範囲の履歴を取得する。Telegramは公式MTProto APIを利用する第三者ライブラリTelethon、Slackは公式Web APIを利用する。SlackのHTTP層はPython標準ライブラリで実装する。

既存のTauri 2＋React/TypeScript＋Rust構成は、デスクトップMVPの設計として保持する。今回のPython採用はGUIのスタック変更ではなく、認証・履歴取得の実現性を先に試すための独立PoCである。Pythonを将来のTauriにそのままバンドルする判断はしていない。

## 優先順位

1. 認証・選択対象・秘密保存・実接続の方法を成立させる。
2. 各サービスの単独取得を試す。
3. 同一実行で2サービス各50件を共通モデルへ変換して混在表示する。
4. その実機証拠を得てから、永続化・検索・UI・送信に進む。

Codexを使用する必要はない。ChatGPTが作成したこのコードをMacで実行し、実行結果を使って修正する。GUI以降のローカルビルド・多数ファイルの編集でコードエージェントを導入するかは、その時点で判断する。

## 元の設計から明示的に修正した点

### セキュリティを後回しにしない

元の説明ではKeychain等を後工程にまとめていたが、実際のログインより前に必要である。PoCでもToken、API hash、TelegramセッションはKeychainへ保存する。平文ファイルや`.session`ファイルへのフォールバックを設けない。

### メッセージの一意性に会話を含める

一意性のキーは`provider + accountId + conversationId + providerMessageId`とする。Telegramの別チャットの同じ数値ID、Slackの会話内timestampを、サービス全体で一意だと仮定しない。JSON配列をSHA-256でハッシュし、単純な区切り文字連結の曖昧性も避ける。

### PoCでは本文を永続化しない

SQLite・FTS・暗号化DBは次の工程とする。今回のLoopに本文永続化は不要であり、先に平文履歴を溜めてしまわないためである。メタデータだけの検証レポートは端末に保存する。

### 2サービスを明示

今回の選択はTelegram＋Slack。Slackアカウントや導入権限の保有は未確認である。そのため、この選択は「実装した接続対象」であり「ユーザーがすでに利用可能な2サービスを確認済み」という意味ではない。

Discord個人Token、自動self-bot、ブラウザのCookie抽出、非公式な認証回避には進まない。Slack前提が満たせない場合、失敗を隠してデモや別サービスで置き換えない。

### PoCが証明する範囲を限定

50件取得は初期接続の技術仮説を検証する。長期安定性、削除・編集反映、全履歴整合性、送信、全サービス対応、商用配布、セキュリティをまとめて証明したことにはしない。

## 将来への引き継ぎ
