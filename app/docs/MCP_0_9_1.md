# 5サービスのローカルMCP — 0.9.1

2026-10-03。LINE・Slackに加えて、Instagram・X・Messengerも同じアプリからMCPへ接続できるようにしました。

## 設定する

1. アプリの左側で対象サービスを選び、本人のアカウントを接続します。
2. 「接続設定」→「MCP接続」→「MCPを有効にする」を押します。
3. クライアント名、許可する会話、権限を選び「この権限で登録」を押します。初期値は閲覧・検索のみで、会話は未選択、送信はオフです。
4. 一度だけ表示されるトークンを、そのMacのAIクライアントへ設定します。接続方式は **Streamable HTTP**、認証ヘッダーは `Authorization: Bearer <表示されたトークン>` です。
5. 取り消すときは対象クライアントの「取り消す」。サービス全体を止めるときは「MCPを停止」です。

| サービス | 初期の接続先URL | 閲覧・検索 | MCPから送る対象 |
|---|---|---|---|
| LINE | `http://127.0.0.1:28641/mcp` | 許可した保存済み会話 | 対応済みの1対1テキスト |
| Slack | `http://127.0.0.1:28642/mcp` | 保存済み会話＋スレッド取得 | 参加済みDM・グループDM・チャンネルのテキスト |
| Instagram | `http://127.0.0.1:28644/mcp` | 許可した保存済み会話 | DM・参加済みグループのテキスト |
| X | `http://127.0.0.1:28645/mcp` | 許可した保存済み会話 | 現在の参加・暗号鍵を確認できるX ChatのDM・グループ |
| Messenger | `http://127.0.0.1:28646/mcp` | 許可した保存済み会話 | 接続中の既存E2EE端末から1対1テキスト |

28643はSlackのOAuthコールバック用です。各MCPポートは設定で変更できますが、別サービスと重複させないでください。MCPサーバー名にもサービス名を付けています。

**登録はサービスごとに独立しています。** 5サービスを使うクライアントには、必要なサービスのURLとトークンをそれぞれ登録します。アプリ起動中に動作し、有効設定は再起動後も復帰します。AIクライアント側にはローカルURL・Streamable HTTP・手動Bearerヘッダーへの対応が必要です。クラウド側からこのMacの `127.0.0.1` に直接接続はできません。

## 公開する操作

| ツール | 動作 |
|---|---|
| `list_conversations` | このトークンに許可した会話だけを返す |
| `get_messages(conversation_id, before?)` | 保存済み履歴を100件ずつ読む。返された `olderCursor` を `before` へ渡すと古いページを取得 |
| `search_messages(query)` | 許可した保存済み会話を検索。最近の最大10,000保存メッセージを対象に、最大50件を返す |
| `send_message(conversation_id, text, request_id)` | 送信権限を持つ会話へテキストを1回送る。`request_id` は意図した送信ごとに作るUUID |
| `get_thread(conversation_id, message_id)` | Slackのみ。保存済みの親メッセージから最大15件のスレッドを取得・保存 |

`conversation_id` はツールが返すローカルIDを使います。閲覧系3操作は外部サービスを呼ばず、端末内の保存データだけを読みます。カーソルがなくても、サービス側の全履歴を取得したことにはなりません。取得範囲は[0.9.0の対応表](INBOX_0_9.md)を引き継ぎます。

Xの旧形式DM本文は読み取り可能ですが、X Chatと同じ署名検証済み本文ではありません。Messengerの過去バックアップ復元、添付送信、新規会話・グループ作成をMCPで追加したものではありません。

## 送信と権限

- 送信を許可したクライアントは、毎回アプリで確認せず送れます。アプリ上でも登録時に説明します。
- 画面で開いていない許可済み会話にも送れます。画面の会話選択・下書きは切り替わりません。
- 同じクライアント・同じUUID・同じ本文の重複要求は1回に抑えます。結果不明の要求は、再起動しても自動再送しません。成功応答は相手の着信・既読の証明ではありません。
- 接続認証や子プロセス起動、書き込みロックを待った後にも権限を確認します。すでに外部へ発行された送信は、後から取り消しても回収できません。
- 保存停止は受信・送信を止め、保存済みの閲覧は残します。閲覧も止める場合はMCP停止か権限取り消しを使います。
- 対象サービスのローカル削除は、そのサービスのMCPを止め、権限も失効させます。他サービスの権限は維持します。

トークンのハッシュと権限は暗号化DBへ保存し、トークンの原文は再表示しません。許可範囲はサービス・アカウント・会話・閲覧／送信です。現行ソースはInstagram・X・Messengerの旧共通設定を引き継ぎません。現行設定がなく旧設定だけが残る場合は停止し、保存停止を無視した収集再開を防ぎます。MCPの有効状態やLINE用の権限は流用しません。0.9.5までは保存停止の引継ぎがありましたが、[開発方針](../../AGENT.md)で廃止しました。

## 検証と残る確認

Core全480件、画面全59件、Rust4件、production build、shell構文6ファイル、offline demoを確認。新3サービスは独立した公式MCP SDKから実際のloopback HTTPへ接続し、一覧・履歴・検索・送信、別サービスのトークン拒否、失効、再起動後の復帰を架空データで検証しました。ほかに保存履歴のページ分割、会話・アカウント分離、重複送信抑止、結果不明の再送禁止、送信直前の失効を確認しています。

この結果は実サービスへのMCP送信・実ユーザーのAIクライアント接続の成功証拠ではありません。今回の実送信は0回。個人データへのMCP権限を作成していません。通常配置の0.8.5は維持し、0.9.1を別の配布候補として作成しています。署名・同梱runtimeの確認結果は[検証記録](desktop-0.9.1-verification.json)を参照してください。
