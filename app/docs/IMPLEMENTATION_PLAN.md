## 初版の商品範囲

次の範囲を初版案として固定し、G0の配布条件確認で成立性を判定する。現行LINE方式を商用提供可能と認定したものではない。

- **対象環境:** Apple Silicon Mac、本人のLINE 1アカウント。対応macOSは配布候補の実機で確認した版を明記する。設定上の最低OSバージョンを動作実績と混同しない。
- **最初の使い道:** 明示選択した1対1テキスト会話を取得・保存・検索し、対応AI 1製品から参照して返信案を作る。返信案は外部AIの機能で、AI契約や利用料金は別。
- **送信:** アプリの明示操作、または利用者が送信権限を与えたAIから許可宛先へ送信。初期状態はMCP無効・送信OFF。宛先・read/send権限を分離し、結果不明の自動再送をしない。
- **取得範囲:** 初版の自動取得は選択1会話。保存済みの許可会話だけをMCPで参照する。最終取得時刻・回収上限・検索範囲を画面とAI応答から確認できるようにする。
- **導入:** アプリ内のLINE認証、対応AIへの設定案内、接続確認、権限取り消し、保存停止・削除までを案内する。利用者がソースを編集する導入方法は標準にしない。
- **配布・更新:** 署名・公証済みアプリ、再ダウンロード、署名済み新版本体への手動更新を初版の最小構成とする。自動更新・常時オンライン認証・複雑なライセンス管理は初版の必須条件にしない。

Instagram・X・Slackの既存コードと検証実績は維持し、追加サービスの中ではSlackを優先候補にする。ただし、各サービスの条件が揃うまで初版の有料対応として約束しない。販売パッケージは対象外の接続部を除外するか、同梱分を含め配布条件を満たす必要がある。ボタンを隠すだけでライセンス確認を済ませない。

Discordは初版後の候補。iMessage・WhatsApp、複数アカウント、全会話の常時監視、添付・グループ・既読同期、全過去履歴の保証は初版に追加しない。削除・保持期限の追従がサービス条件上必要なら、単なる対象外扱いではなくG0/G2の要件にする。

### G1/G2: AIと日常運用

- 対応AIは実際にローカル接続と必要な認証方式を使える1製品で確認する。現MCPはloopbackのStreamable HTTPと手動Bearerであり、すべてのAI製品で使えるとは表示しない。
- 実接続では利用者がAI・会話・権限を選ぶ。送信テストは承認済みの宛先・本文のみ。受信メッセージ内の指示を権限変更と扱わず、未許可会話・別アカウント・失効済み権限からの取得と送信を拒否する。
- 受信回収の上限未満/上限到達/超過を区別する。完全同期を初版へ必須追加する代わりに、回収可能範囲と確認できない空白を明示する。上限超過を黙って「同期完了」にしない。
- LINEの保存停止・権限失効・アカウント限定削除は、同意した試験用データで検証する。普段の会話を検証目的で削除しない。エラー報告に本文・宛先・鍵・トークン・検索語を含めない。
- 販売候補では同梱依存と外部通信を確認する。運営者に送らないデータと、利用者が選ぶ外部AIへ渡るデータを説明する。「一切外部に出ない」とは表示しない。

### G3/G5: 配布と運営

正式署名は完成済みなので作り直さず、[Appleの公証工程](https://developer.apple.com/developer-id/)と別Macでの導入・更新を追加する。署名済みであることと公証済みであることを分けて記録する。

既存の販売ページ・価格・返金方針を基に、配布ファイル、受け渡し方法、再ダウンロード、対応環境、購入時の同意、サポート窓口、更新範囲を揃える。Stripeの本人情報・入金先・最終申請が必要な部分は本人作業として残し、それまでに設定内容とテスト購入の手順を準備する。今回の計画変更を、外部への連絡・申請送信・課金・販売開始の実行許可には使わない。

発売を妨げる問題は、認証不能、誤宛先/二重送信、無断アクセス、保存破損、重要な取得失敗の黙認、初回導入不能、購入後の配布不能、配布条件未解決。試用期間に見つかった場合は修正後に該当条件を再確認する。
